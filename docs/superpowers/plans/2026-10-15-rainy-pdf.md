# RAINY PDF Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for native task-by-task implementation, or superpowers:subagent-driven-development if the user selects that execution method. Steps use checkbox syntax for tracking.

**Goal:** Ship a Mongolian offline Windows PDF editor with the approved editing, redaction, printing, OCR, Word and Excel conversion features and a tested installer.

**Architecture:** A PySide6 desktop editor owns an immutable document session and edit history. A PyMuPDF adapter applies PDF edits; process workers handle OCR/conversions/export against a serialized session snapshot. Tesseract and LibreOffice are bundled runtime dependencies, with adapters and fixture tests insulating the UI from library limitations.

**Tech Stack:** Python 3.12, PySide6, PyMuPDF, Pillow, Tesseract 5 mon/eng/osd, pdf2docx, python-docx, openpyxl, LibreOffice, pytest/pytest-qt, PyInstaller, Inno Setup.

**Spec:** `docs/superpowers/specs/2026-10-15-rainy-pdf-design.md`

## Global Constraints
- Windows 10/11 x64; no Python, Office, OCR or LibreOffice installation required from the end user.
- Mongolian UI, light blue R branding; all document processing offline; no document telemetry.
- First release includes editing, page operations, true redaction, Undo/Redo, preview/print, OCR and PDF ↔ Word/Excel.
- AGPLv3-compatible open-source distribution, with bundled third-party license texts and source pointers; no proprietary Acrobat code/assets.
- Save As by default, source unchanged, atomic validated output, explicit overwrite choice and temporary-file cleanup.
- Unsupported editing and conversion cases produce an actionable Mongolian result; no silent text truncation or fake success.
- Scanned text editing does not alter underlying scan pixels; searchable OCR and editable exports are distinct outputs.
- Digital certificate signing and arbitrary paragraph reflow are later scope, not release claims.
- Pin tested dependency versions and runtime hashes during Task 1/13; never use unverified latest binaries in a published installer.

## Review Focus
1. Cropped/rotated PDF pages: coordinates must map correctly at every zoom (Tasks 2, 7).
2. Mongolian Cyrillic glyph coverage: added/exported text must retain Ө/Ү and mixed scripts (Tasks 3, 9, 10).
3. Redacted words in hidden layers/annotations/metadata: output must not retain the selected sensitive string in tested channels (Task 4).
4. Cancellation or disk-full errors during export: neither source nor pre-existing output may change (Tasks 1, 8).
5. Spreadsheet identifiers/formula-looking strings and hostile Office automation: preserve literal cells, disable macros and link updates (Tasks 11, 12).

## Source findings (2026-10-15)
- PyMuPDF provides render/edit/annotation/redaction under AGPL/commercial terms: https://github.com/pymupdf/PyMuPDF
- pdf2docx is MIT and no longer actively maintained by Artifex. Pin a tested release; isolate behind adapter; capture regressions before vendoring or maintaining a fork: https://github.com/ArtifexSoftware/pdf2docx
- Tesseract language models: https://github.com/tesseract-ocr/tessdata_fast and https://github.com/tesseract-ocr/tessdata_best . Bundle mon/eng plus osd from a compatible repository. Measure fast vs best on fixed Mongolian fixtures before selecting release data.
- LibreOffice conversion and license: https://help.libreoffice.org/latest/en-US/text/shared/guide/pdf_params.html and https://www.libreoffice.org/licenses/
- Qt/PySide licensing: https://github.com/pyside/pyside-setup

## File map
- `src/rainypdf/domain/`: types, document session, bounded history and serializable commands.
- `src/rainypdf/engine/`: PDF open/render/coordinates/fonts/edits/annotations/pages/output.
- `src/rainypdf/conversion/`: OCR, DOCX, XLSX and Office runtime adapters.
- `src/rainypdf/jobs/`: process protocol, cancellation and temporary workspace ownership.
- `src/rainypdf/ui/`: main window, home, canvas, thumbnails, tool properties, conversion dialogs and print preview.
- `src/rainypdf/storage/`: preferences and recent paths only.
- `tests/fixtures/`: generated synthetic documents and expected text/cell/image results; no private user files.
- `build-tools/`, `installer.iss`, `.github/workflows/`: verified runtimes, packaging and Windows release validation.

## Shared interfaces
Dataclasses in `domain/types.py`: `Rect(x0,y0,x1,y1)`, `Command(kind:str,page_id:str,payload:dict)`, `SessionSnapshot(source:Path,commands:tuple[Command,...],generation:int)`, `JobRequest(id:str,kind:str,snapshot:SessionSnapshot|None,options:dict,output:Path)`, `JobEvent(id:str,generation:int,state:str,progress:float,message:str,output:Path|None)`.
`DocumentSession.open(path:Path,password:str|None)->DocumentSession`; `snapshot()->SessionSnapshot`; `apply(command:Command)->None`; `undo()->bool`; `redo()->bool`; `dirty:bool`. Password remains memory-only and crosses only the owned worker IPC where necessary.
`PdfEngine.render(snapshot:SessionSnapshot,page_id:str,scale:float)->RenderedPage`; `materialize(snapshot:SessionSnapshot)->bytes`.
`JobManager.submit(request:JobRequest)->str`; `cancel(job_id:str)->None`; callbacks deliver `JobEvent` on Qt main thread. Discard stale generation results for display; completed user-requested exports retain their output and status.
`atomic_export(destination:Path,writer:Callable[[Path],None],validator:Callable[[Path],None],overwrite:bool=False)->Path`.

## Integration order and completion gates
Tasks 1–8 establish the editor; 9–12 integrate document recognition/conversions; 13–14 integrate printing and distribute one installer. These are implementation milestones within the same agreed release, not reasons to omit OCR or Office conversion from that release.

After each task, update this checklist and record actual commands/results. Before release: whole-branch code review, full test run on Linux where supported and Windows packaged run, fixture render inspection, source/license notices, no credentials/documents in artifacts. A green unit suite alone does not establish installer or real-printer success.
